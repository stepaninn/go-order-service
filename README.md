# Сервис заказов на Go

REST API для создания заказов, расчёта их стоимости и отслеживания статусов. Сервис хранит заказы и историю статусов в памяти, поэтому после перезапуска данные сбрасываются. Для запуска достаточно Go 1.22 или новее.

## Быстрый старт

```bash
go mod download
go run ./cmd/api
```

По умолчанию сервер слушает порт `8080`. Адрес можно задать через переменную `HTTP_ADDR`, например `HTTP_ADDR=127.0.0.1:8081`. Запрос `curl http://localhost:8080/health` возвращает `{"status":"ok"}`.

После запуска API можно проверить в [Swagger UI](http://localhost:8080/swagger/index.html) или открыть [спецификацию в JSON](http://localhost:8080/swagger/doc.json).

## Эндпоинты

| Метод | Путь | Назначение | HTTP-код |
| --- | --- | --- | --- |
| `GET` | `/health` | Проверка доступности | `200` |
| `POST` | `/api/v1/orders` | Создание заказа | `201` |
| `GET` | `/api/v1/orders` | Список заказов | `200` |
| `GET` | `/api/v1/orders/{id}` | Получение заказа по ID | `200` |
| `PATCH` | `/api/v1/orders/{id}/status` | Изменение статуса | `200` |
| `GET` | `/api/v1/orders/{id}/history` | История статусов | `200` |

### Пример работы с заказом

Создайте заказ из двух клавиатур по 5 000 ₽ за штуку. API использует целые числа в копейках для цены товара (`price`) и итоговой стоимости (`total_price`).

```bash
curl -fsS http://localhost:8080/api/v1/orders \
  -H 'Content-Type: application/json' \
  -d '{"items":[{"name":"Keyboard","quantity":2,"price":500000}]}'
```

Сервер присвоит заказу положительный целочисленный ID и вернёт заказ с итоговой стоимостью `1000000`, статусом `new` и временем создания. В следующих командах используется ID `1`. Если в ответе пришёл другой ID, подставьте его в URL.

```bash
curl -fsS http://localhost:8080/api/v1/orders/1

curl -fsS -X PATCH http://localhost:8080/api/v1/orders/1/status \
  -H 'Content-Type: application/json' \
  -d '{"status":"processing"}'

curl -fsS http://localhost:8080/api/v1/orders/1/history
```

История содержит начальный статус и все последующие изменения. Записи возвращаются от ранних к поздним с полями `status` и `changed_at`. Список заказов также отсортирован от ранних к поздним и возвращает `[]`, если заказов ещё нет. Время в ответах указано в UTC.

### Правила для заказов

Заказ должен содержать хотя бы один товар. Название товара должно содержать хотя бы один непробельный символ. Количество и цена должны быть положительными. Сумма произведений цены на количество по всем позициям должна помещаться в `int64`.

| Текущий статус | Допустимые переходы |
| --- | --- |
| `new` | `processing`, `cancelled` |
| `processing` | `completed`, `cancelled` |
| `completed`, `cancelled` | Конечные статусы |

При успешном переходе API возвращает обновлённый заказ и сохраняет изменение в истории. Повторная установка текущего статуса возвращает `409 Conflict`.

### Ошибки API

Обработчики заказов возвращают ошибки с текстом в поле `error` и кодом в поле `code`.

```json
{
  "error": "status transition is not allowed",
  "code": "INVALID_STATUS_TRANSITION"
}
```

| HTTP-код | Поле `code` | Причина |
| --- | --- | --- |
| `400` | `INVALID_JSON` | Некорректный JSON, неизвестные поля или несколько JSON-значений в теле запроса |
| `400` | `INVALID_ID` | Некорректный идентификатор |
| `400` | `INVALID_ORDER` | Заказ не прошёл валидацию |
| `400` | `INVALID_STATUS` | Неизвестный или пустой статус |
| `404` | `ORDER_NOT_FOUND` | Заказ не найден |
| `409` | `INVALID_STATUS_TRANSITION` | Переход статуса запрещён |
| `500` | `INTERNAL_ERROR` | Внутренняя ошибка |

## Структура проекта

| Путь | Назначение |
| --- | --- |
| [`cmd/api/`](cmd/api/) | Точка входа и настройка сервера |
| [`internal/handler/`](internal/handler/) | Маршруты Chi, HTTP-обработчики, разбор JSON и middleware |
| [`internal/service/`](internal/service/) | Валидация, расчёт стоимости, переходы статусов и модульные тесты |
| [`internal/order/`](internal/order/) | Модели заказов и интерфейс репозитория |
| [`internal/repository/memory/`](internal/repository/memory/) | Хранилище в памяти с защитой доступа через мьютекс |
| [`docs/`](docs/) | Сгенерированная документация Swagger |

Сервер выдаёт каждому запросу `X-Request-ID` и записывает этот же идентификатор в JSON-логи через `log/slog`. Журнал запросов содержит метод, путь, HTTP-статус, длительность и признак прерванного запроса. При панике middleware записывает детали в лог и возвращает `500`, если отправка ответа ещё не началась. Если отправка уже началась, middleware прерывает запрос.

## Тесты и документация

```bash
go test ./...
go test ./internal/service/... -cover
go vet ./...
go build ./...
```

Модульные тесты проверяют валидацию заказа, расчёт стоимости, получение заказов, переходы статусов и порядок записей в истории.

После правок Swagger-аннотаций запустите `go generate ./...`. Команда использует версию Swaggo из `go.mod` и обновляет файлы в `docs/`.
